# Pockets

Keep reusable facts together by topic. These portal pockets are portable raw-fact collections with provenance.

## Simple

### Create and fill a pocket

Create a pocket for one topic. Select approved reusable queue items and extract them into it. Open the member list to check the statements and remaining capacity.

### Share a pocket

Export a pocket package. To add a shared pocket, import its package under a new ID. Inspect the facts and provenance before using them in your learning workflow.

## Advanced

### Copy or combine

Copy all members or selected facts into a new pocket. Merge pockets that share the same declared topic into a new collection with enough capacity. The sources remain available.

### Continue a full pocket

Rollover seals a full open pocket and creates an empty successor for the same topic. Export before removing a catalog pocket you want to preserve. Native teacher retirement uses the separate trigger runbook after recall qualification.

## Settings and details

### Item ID

A new ID uses 1 to 64 lowercase letters, numbers, underscores or hyphens, starting with a letter or number. IDs identify rules, jobs and pockets. Copies, imports, merges and successors need an unused target ID.

### Topic

A safe ID for the pocket's single declared topic. Merges require all source topics to match. Topic is a declared label; review the members for relevance.

### Capacity

The maximum number of raw facts, from 1 to 2000. Extraction, import, copy and merge enforce it. A full open pocket can roll over to an empty successor with its own capacity.

### Candidate IDs

Select 1 to 200 approved reusable queue items. Extraction verifies their current approval and update targets, then records their source provenance. Memory-routed items belong in the memory handoff.

### Fact IDs

Copy selected existing members by ID, or omit the selection to copy every member. Unknown or repeated IDs are rejected.

### Merge sources

Choose at least two source pockets of the same topic. Identical fact IDs with identical content are kept once; conflicting content under one ID blocks the merge.

### Shared package

A version-1 raw_facts package carries ID, topic, capacity, statements, provenance and a SHA-256 content seal. Import verifies the seal and creates a local shared catalog. Tensor acceptance and learning remain separate lifecycle steps.

### Pocket state

Open pockets accept approved members. Rollover seals the full source and records its successor. Shared marks an imported package. Removing a portal catalog entry changes admin storage; native teacher slots are owned by the trigger lifecycle.
